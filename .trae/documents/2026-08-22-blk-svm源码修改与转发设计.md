## 一、Forwarding 设计总览

远程 virtio-blk SVM：**local QEMU（本地机）+ remote stub（远端机）**，通过 TCP socket（`127.0.0.1:5552`）转发 virtio-blk 请求/响应，配合 `vr.conf` 参数（`zc_send_min / workers / inflight_size / local_batch_n / stub_batch_n / buf_pool`）调节流水线。

```
guest virtio-blk 队列
        │ virtio_ring (pop/push)
   local QEMU（mosaic virtio-blk 设备）
        │ 请求线格式：[vq_nr][seq][out_num][in_num][lens...][out data...]
        │ TCP（非阻塞 + NODELAY）
   remote stub（独立进程，持有真实磁盘 data.raw）
        │ 解析请求 → 直接 libaio/同步 IO 到磁盘 → 响应线格式：[vq_nr][seq][len][in data...]
        │ TCP
   local QEMU 收到响应 → 校验 vq_nr/seq → push used ring
```

### 1. 流水线与 inflight 窗口

- **两端均有 inflight 窗口**：lock-free SPSC 环形（`Inflight`，power-of-2，`head` 消费方 / `tail` 生产方），槽位存 `VirtQueueElement *`（local）或 `StubResp *`（stub）。
- **local 端**：pop → 发送 → 入窗 → 收响应 push；窗口满时发送 worker 在 `full_cond/full_lock`（= vq_lock）上阻塞（背压）。
- **stub 端**：窗口满时 push 路径在自有 `push_lock/push_cond` 上等待。
- **零拷贝**：响应长度 ≥ `zc_send_min`（固定 1MB）时走 `MSG_ZEROCOPY`。zc 发送后内核仍引用缓冲页（TCP delayed ACK 可能延迟 ~40ms），因此 **used-ring push 必须推迟到 zc 完成**（`ZcPending.serial` + `len_known`），否则 4KB 响应会出现 40ms 延迟平台（tier6 崩溃根因）。zc 完成以 socket `POLLERR` 信号投递，由 send worker 收割。

### 2. worker 池（WorkerPool）

- **local**：send pool + recv pool；**stub**：recv(handle) pool + send pool。
- `worker_pool_worker(pool, vq)` 按 vq 哈希到**固定** worker，保证同一 vq 的发送/接收单线程串行，是 SPSC 无锁的前提。

### 3. aio fd handler 模型（本实验修复的核心约束）

- qemu **一个 fd 只能在一个 aio context 上注册 handler**（`aio_set_fd_handler` 单 ctx）。
- stub 的读 handler `stub_distributor`（POLLIN）注册在**主 aio ctx**（`vq_get_aio_ctx(vq)`）。
- 因此 stub 发送 EAGAIN 时，POLLOUT 的 writable handler **必须注册在同一主 ctx**（`stub_distributor, stub_send_writable` 成对注册），恢复时再还原 read handler。

### 4. 非阻塞短写恢复

- 发送一律非阻塞；`EAGAIN` → 保留现场，注册 writable handler，等可写再重入。
- **短写（ret < 请求字节）**：
  - local：把未发送尾快照进 `LocalSendResume`（copy elem 快照 header/lens/out_sg 指针；zc elem 快照私有 tail 缓冲，因为 zc completion 可能已释放原 bufs）。
  - stub：`StubResp->sent` 记录已发字节，恢复时 `stub_resp_iov_tail()` 重排尾部 iov。
- 响应合批：stub 把连续多个 copy 响应合并为一次 `sendmsg`（`stub_send_batch`），zc 响应会先冲刷待发批。

### 5. 线格式与序列化

- 请求头 `[vq_nr][seq][out_num][in_num]` + `(out_num+in_num)` 个长度 + out 数据。
- 响应头 `[vq_nr][seq][in_num 个长度]` + in 数据。
- `seq` 为 elem index，local 收响应时校验 `vq_nr/seq` 防止多 vq 字节流 desync（曾出现的崩溃签名 `resp vq_nr 0, expected N`）。

## 二、本次实验过程中修改的源码

### A. 本会话（2026-08-22，均已编译验证）

**A1. `local_send_resume` copy-elem iov clip 下界修复（约 1794-1829）**
- 原 bug：`if (off < seg_off + olen)` 缺少 `off >= seg_off` 下界，off 落在前段时，后续段 `(off - seg_off)` 无符号回绕 → 巨大 `iov_len` → `sendmsg EINVAL` → elem 丢弃 → 请求永久挂起。
- 现场：`off=156824 total=393444 k=25 zc=0`，`iov[1].len=18446744069414599756`（spark 20+ 段请求触发）。
- 修复：`size_t in_seg = (off > seg_off) ? (off - seg_off) : 0;`（header/lens/out 三段分支统一加保护）。

**A2. `local_send_resume` 错误现场打印（约 1846-1852）**
- sendmsg 失败时打印 `off/total/k/zc/payload` + 每个 iov len，且**在 `g_free(sg)` 之前**打印（避免 use-after-free）。

**A3. stub 侧 EAGAIN writable 注册修复（3 处）**
- `stub_send_batch` 完整 EAGAIN（约 3270-3272）、`stub_send_batch` 中途短写 EAGAIN（约 3302-3304）、`stub_send_task` 单响应 EAGAIN（约 3498-3500）。
- 原代码 `aio_set_fd_handler(w->ctx, ...)` 注册在 worker 私有 ctx，与主 ctx 的 read handler 冲突（单 fd 单 ctx）→ POLLOUT 永不触发 → **4MB zc 响应短写后永久挂起**（spark app 卡死根因）。
- 统一改为：
```c
ctx->send_full = true;
aio_set_fd_handler(vq_get_aio_ctx(vq), fd,
                   stub_distributor, stub_send_writable,
                   NULL, NULL, vq);
```

**A4. `stub_send_writable` handler 清除（约 3624-3631）**
- 原 `aio_set_fd_handler(w->ctx, ..., NULL...)` 清除用错 ctx。
- 改为 `vq_get_aio_ctx(vq)` 上清除 POLLOUT，并**恢复 `stub_distributor` 的 read handler**（`stub_distributor, NULL`），删除不再使用的 `Worker *w`。

**A5. `stub_send_detach` 连接拆除时的 handler 清理（约 3131-3140）**
- 同样由 `w->ctx` 改为 `vq_get_aio_ctx(vq)`（`stub_send_err_teardown` 已用正确 ctx）。

### B. 前期（同一实验周期内）关键修改

**B1. `stub_resp_copy_range` from/off 推进 bug（约 3187-3206）**
- 原实现同时推进 `from` 和 `off`，导致首段之后每段错位 → 32 路并发读下多 vq 字节流 desync（`resp vq_nr 0` 崩溃）。修复为线性单游标推进。

**B2. local zc 短写尾快照**
- 4MB 读响应短写时同步快照 unsent tail（`LocalSendResume` zc 分支），因 `stub_zc_drain` 可能已释放原 bufs。

**B3. 诊断插桩（vr_ev_log 事件环）**
- `VR_EV_*`（1-40）lock-free 环形缓冲（`VR_EV_N=262144`，`vr_ev_pos` 原子推进）；`SIGUSR1` 可 dump 到 `/tmp/vr_ring_dump_local.txt` / `/tmp/vr_ring_dump_stub.txt`。
- `vr_ev_log_ext()` 供 `virtio.c` / `virtio-blk.c` 记录 attach/detach/drain 事件。
- `stub_log_send_probe`（SRES/SRDMP）：sendmsg 前记录精确 iov 与首 8 字节，用于核对 "ret=128 但仅 63 字节入队" 的 zc-resume 尾滴异常。
- `stub_send_batch` 批头全零探测：若批头 header 全 0（`resp vq_nr 0` 崩溃签名）先打印 header 内存。

**B4. `fdmon-io_uring.c`（+71 行）**
- 为 iothread/io_uring 场景补充的监控适配（配合单 fd 单 ctx 的 handler 模型）。

## 三、关键设计约束备忘（后续开发须遵守）

1. **单 fd 单 aio ctx**：任何 POLLOUT/POLLIN handler 注册/清除都必须用 `vq_get_aio_ctx(vq)`（stub 主 ctx），禁止用 worker 私有 ctx；清除时恢复另一方向 handler。
2. **zc 完成前不释放缓冲**：`MSG_ZEROCOPY` 发送后，header/iov/in bufs 由 zc 完成（POLLERR）收割，短写恢复只能用私有快照。
3. **SPSC 无锁依赖固定 worker**：同一 vq 的 recv/send 必须哈希到同一 worker，不能跨 worker 并发操作窗口。
4. **响应 push 与 zc 完成绑定**：`len_known` 之前不得 push used ring，避免延迟 ACK 平台。
