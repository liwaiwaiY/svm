# 实验矩阵（2026-08-19 确认版）

> 本文档是后续所有实验的执行依据。矩阵由用户提供并确认，含 KVM baseline 与 SVM 两阶段。

## 1. 术语

- **KVM**：传统 QEMU/KVM，无 remote stub。设备后端运行在 local qemu 进程内。
  - crypto：`virtio-crypto` + `cryptodev-backend-builtin`（本地后端）
  - blk：`virtio-blk` 本地磁盘（O_DIRECT，`cache=none`）
- **SVM**：本项目 virtio-remote 机制。local qemu 前端 + remote stub 后端，设备请求经 TCP 发送到 stub 处理。
  - crypto：`virtio-crypto-pci,cryptodev=cryptodev0,remote-machine=127.0.0.1@5553`
  - blk：`virtio-blk-pci,remote-machine=127.0.0.1@5552`

## 2. 通用规范（重要）

### 2.1 Page Cache 禁用（blk 实验强制）

host 与 guest 都可能启用 page cache，污染 fio/openssl 测量结果。**所有 blk 实验必须**：

- **host 侧（qemu 与 stub 的磁盘）**：`-drive ... ,cache=none`（O_DIRECT），禁用 host page cache
- **guest 侧**：fio 一律加 `--direct=1`（O_DIRECT，绕过 guest page cache）

```bash
# host qemu/stub 磁盘示例
-drive file=~/svm/exp/local/kvm/data.raw,if=none,id=drive1,format=raw,cache=none
```

### 2.2 环境

- host 端 qemu：`local_qemu/build/qemu-system-x86_64`
- guest：Ubuntu 26.04，SSH `ssh -p 2222 wai@127.0.0.1`（密码 wai）
- guest 数据盘：`/dev/vdb`（serial=data-disk），挂载点 `/mnt/data`，需先格式化挂载
- 启动方式：不用 `-nographic`（SeaBIOS 挤占终端），用 `-serial file:guest.log -monitor none -display none -qmp unix:/tmp/qmp.sock,server,nowait`

### 2.3 产出与数据存储格式

每个实验点用一个 JSON 对象 `{}` 记录（追加到 `exp_results/<exp>/*.jsonl`，每行一个对象，便于脚本处理与审查）。必填字段帮助审查：

```json
{
  "dev": "crypto",                 // 设备：crypto / blk
  "exp": "M1",                     // 机制：M1-M5 / Macro / App
  "variant": "SVM-档0-基准",        // 变体点：KVM / SVM-档N / SVM-<参数档描述>
  "env": {"VR_ZC_SEND_MIN": 4096}, // 该变体点的运行期参数（SVM 档；KVM 可省略）
  "command": "openssl speed -engine afalg ...",  // 完整 bench 命令（含全部参数）
  "result": "..."                  // bench 输出关键数据（粘贴，见第 4 节各实验要求）
}
```

- 每个 `{}` 记录对应一次 bench 运行；同一变体点多次运行可并列多个对象（注明 run 序号）
- 原始完整日志另存 `exp_results/<exp>/logs/`，`result` 只放关键数据
- 汇总表（CSV/MD）与曲线图（gnuplot/matplotlib）由 jsonl 生成
- 参考现有格式：`exp_results/kvm.txt`（草稿，字段待按此规范统一）

## 4. 各机制执行细节（bench 参数规范）

> 通用约定：fio 一律 `--ioengine=libaio --direct=1 --runtime=60 --time_based --group_reporting`（guest 侧 O_DIRECT 绕过 page cache）；数据盘 `/dev/vdb` 需已格式化挂载。每个变体点跑 3 次取稳定值，result 记录每次关键数据。

### M1 zc 阈值（crypto / openssl speed）

```bash
openssl speed -engine afalg -elapsed aes-128-cbc   # openssl 自带 16/64/256/1K/8K/16K blocksize
```
- 前置：guest 卸载 `aesni_intel`，使 crypto API 走 `virtio_crypto_aes_cbc`
- 变体：`VR_ZC_SEND_MIN` ∈ {0, 4096, 65536, 524288}（档 0-3）
- **result 记录**：speed 表每行（各 blocksize 的 MB/s / 1000s 处理量），转成 blocksize-throughput 曲线

### M2 worker 池（blk / fio 四负载）

```bash
# rw 依次替换：randread / randwrite / read / write（= randrd/randwt/seqrd/seqwt）
fio --name=M2 --filename=/dev/vdb --rw=randread --bs=4k --numjobs=4 \
    --iodepth=16 --ioengine=libaio --direct=1 --runtime=60 --time_based --group_reporting
```
- **固定**：`--numjobs=4`（jobs 固定为 4）；`--iodepth=16`
- **blocksize**：默认 `--bs=4k`；实验期可加测多个 bs（4K/64K/1M），每个 bs 单独一条记录，形成 bs-iops 曲线
- 变体：`VR_WORKERS` ∈ {1, 2, 4}（档 0/4/5）
- **result 记录**：每种 rw 的 `IOPS`、`BW(MB/s)`、`lat percentiles`（clat p50/p99）

### M3 inflight 深度（blk / fio randrw）

```bash
fio --name=M3 --filename=/dev/vdb --rw=randrw --rwmixread=70 --bs=4k \
    --numjobs=1 --iodepth=32 --ioengine=libaio --direct=1 \
    --runtime=60 --time_based --group_reporting
```
- **固定**：`--numjobs=1`、`--iodepth=32`、`--bs=4k`、rwmixread=70
- **变体 A**：`VR_INFLIGHT_SIZE` ∈ {16, 32}（档 0/6）
- **变体 B（RTT）**：netem 在 local↔stub 链路加 RTT ∈ {0, 50, 100, 150us}，每个 RTT 一条记录（KVM 无 RTT 概念，仅本地环回值）
- **result 记录**：每个 (inflight, RTT) 组合的 IOPS/BW/p99，转 RTT-iops 曲线

### M4 batch（blk / fio randrw）

```bash
fio --name=M4 --filename=/dev/vdb --rw=randrw --rwmixread=70 --bs=4k \
    --numjobs=1 --iodepth=32 --ioengine=libaio --direct=1 \
    --runtime=60 --time_based --group_reporting
```
- **固定**：`--numjobs=1`、`--bs=4k`、rwmixread=70
- **iodepth 扫描**（产出 iodepth-iops 曲线）：`--iodepth` ∈ {1, 16, 32, 64, 128}，每个值一条记录（2026-08-24 重做，含无冗余基线点 1）
- 变体：`VR_LOCAL_BATCH_N=VR_STUB_BATCH_N` ∈ {1, 16, 32}（N=1 关 batch）；`inflight_size=256`（窗口不干预 iodepth≤128）；`batch_m=512K`（默认 64K 会截断 32×4K 批）
- `VR_ZC_SEND_MIN=65536`（64K）：4K 的 fio 请求 < 64K 全走 copy 路径触发 batch（M4 的 Z 固定 64K，与 M1 的 64K 档重叠共享；记录于 env 字段）
- **result 记录**：每个 (batch, iodepth) 的 IOPS/BW/p99

### M5 buffer 池化（crypto / openssl speed）

```bash
openssl speed -engine afalg -elapsed aes-128-cbc
```
- 变体：`VR_BUF_POOL` off/on（档 0/9）——**pool 代码待实现**
- **result 记录**：同 M1，blocksize-throughput

### Macro（blk / sysbench tpcc）

```bash
# Percona sysbench-tpcc（tpcc.lua），需先 prepare 一次
cd ~/sysbench-tpcc
sysbench --db-driver=mysql --mysql-host=127.0.0.1 --mysql-port=3306 \
    --mysql-user=sbtest --mysql-password=sbtest --mysql-db=tpcc \
    --tables=1 --scale=1 --time=60 --threads=<W> ./tpcc.lua run
```
- 变体：`--threads` = `VR_WORKERS` ∈ {1, 2, 4}（档 0/4/5）
- **result 记录**：`transactions/sec`(TPS)、avg latency、95th percentile
- 前置：guest 装 MySQL 8.4 + Percona sysbench-tpcc（tpcc.lua 依赖同目录 tpcc_common/tpcc_run/tpcc_check.lua，需 cd 到该目录执行），数据落 `/dev/vdb` 所在 FS

### App（blk / pyspark + wiki + pagerank）

- 变体：`VR_WORKERS` ∈ {1, 2, 4}（档 0/4/5）
- 负载：`pagerank.py`（`exp/app/pagerank.py`，PySpark 迭代 PageRank，damping=0.85）读 wiki 边表，迭代 10 轮
- 数据：**wiki-Talk-1m** = SNAP wiki-Talk（502 万边）每 5 行抽 1 行，约 100 万边 / 13MB，固定输入（KVM/SVM 同文件）
- 数据规模控制：单轮 ≤10 分钟（KVM 实测 ~40s，SVM 预计 2-3× 仍达标）；原始 5M 全集保留在 `/mnt/data/wiki/wiki-Talk.txt` 备用
- 运行：`spark-submit --master local[N] pagerank.py <edge_file> 10 N`，`--spark.local.dir=/mnt/data/spark-tmp`
- **result 记录**：总耗时 wall time、build/每迭代/sort 分段时间，cores 1/2/4 对比
- 前置：guest 装 Spark 4.2.0（需 Java 17）+ pyspark（随包），wiki 数据放 `/mnt/data/wiki/`

## 5. 运行期参数规划（编译 1 次，单变量扫描）

### 5.1 运行期参数（环境变量，local 与 stub 需设置相同值）

| 参数 | 环境变量 | 默认 | 机制 | 说明 |
|---|---|---|---|---|
| ZC 阈值 | `VR_ZC_SEND_MIN` | 4096 | M1 | 0=全走 zc；>=512K 请求几乎全走 copy |
| Worker 池 | `VR_WORKERS` | 4 | M2、Macro、App | 1/2/4，0 会被钳到 1 |
| Inflight 窗口 | `VR_INFLIGHT_SIZE` | 0（=pow2ceil(vring.num)） | M3 | 16/32；0 表示设备默认 |
| Local batch 上限 | `VR_LOCAL_BATCH_N` / `VR_LOCAL_BATCH_M` | 4 / 64K | M4 | N=1 关闭 batch |
| Stub batch 上限 | `VR_STUB_BATCH_N` / `VR_STUB_BATCH_M` | 4 / 64K | M4 | N=1 关闭 batch |
| Buffer 池 | `VR_BUF_POOL` | off | M5 | ⏳ 待实现（同机制） |

> 实现：`vr_config_init()`（virtio-remote.c L305）在首次使用时读一次 env 到全局变量，运行中不变——与编译期等价。**单次编译**，每个实验点 = 改 env + 重启 local/stub 进程。
> 已实施：`ZC_SEND_MIN`、`VIRTIO_REMOTE_WORKERS`、inflight 窗口、batch 均已运行期化；`VR_DEBUG` 已还原为 0。M5 pool 待实现时同样用 `VR_BUF_POOL`。

### 5.3 SVM：参数档执行（编译 1 次，单变量有效 + 档间共享）

核心思路：所有机制的"固定参数"统一取每个维度的一个变体值 → 形成**基准档 0** `(4K, 4W, 32I, 16B, off)`，它同时是 M1/M2/M3/M4/M5/Macro/App 各自的一个变体点，一次采集贡献 7 个实验点。其余档只偏离一个维度。

| 档 | Z | W | I | B | P | 该档共享执行 |
|---|---|---|---|---|---|---|
| **0（基准）** | 4K | 4 | 32 | 16 | off | M1(4K)、M2(4W)、M3(32)、M4(16)、M5(off)、Macro(4W)、App(4W) |
| 1 | 0 | 4 | 32 | 16 | off | M1(0=全zc) |
| 2 | 64K | 4 | 32 | 16 | off | M1(64K=zc2)、**M4(16)** |
| 3 | 512K | 4 | 32 | 16 | off | M1(512K=全copy) |
| 4 | 4K | 1 | 32 | 16 | off | M2(1W)、Macro(1W)、App(1W) |
| 5 | 4K | 2 | 32 | 16 | off | M2(2W)、Macro(2W)、App(2W) |
| 6 | 4K | 4 | 16 | 16 | off | M3(16) |
| 7 | 64K | 4 | 32 | 1 | off | M4(1=无batch) |
| 8 | 64K | 4 | 32 | 4 | off | M4(4) |
| 9 | 4K | 4 | 32 | 16 | **on** | M5(on) |

单变量校验（各机制内部变体点的其余参数完全一致）：
- M1：档 0-3（Z 变，其余 `4/32/16/off` 相同）✓
- M2：档 0/4/5（W 变，其余 `4K/32/16/off` 相同）✓
- M3：档 0/6（I 变）✓
- M4：档 2/7/8（B 变，其余 `64K/4/32/off` 相同；Z 固定 64K 使 4K 请求全走 copy）✓
- M5：档 0/9（P 变）✓
- Macro/App：档 0/4/5（W 变）✓

最小性：M1 需 4 档（Z 有 4 值）+ M2 额外 2 档（1W/2W）+ M3 额外 1 档（16）+ M4 额外 2 档（1/4）+ M5 额外 1 档（on）= **10 档**，是单变量约束下的下界。

### 5.4 总体执行顺序

```
阶段 0：代码前置（crypto remote 链路跑通 + M5 buffer pool 实现）
阶段 1：KVM baseline（0 次编译）
  1.1 M1/M5 KVM：local-crypto.sh 采 openssl speed（卸载 aesni）
  1.2 M2/M3/M4 KVM：local-blk.sh（cache=none）采 fio（direct=1）
  1.3 Macro/App KVM：装 MySQL/sysbench、spark 后采集
阶段 2：SVM（1 次编译，按参数档序 0 → 1 → ... → 9）
  每档：export 该档 VR_* 环境变量 → 启动 stub + local qemu → 跑该档清单全部实验
        → 记录结果 → 重启下一档
```
